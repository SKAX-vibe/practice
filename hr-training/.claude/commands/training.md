# 교육 이수 현황 (Day 1 업무 도구)

대상 과정: `$ARGUMENTS`

업무 규칙(기한, 신규 입사자 판별, 지연, 기한 후 수료, 확인 필요, 표기, 제약)과 공식 보고서 형식은 `CLAUDE.md`를 따른다.
독려 초안 작성과 검증 결과 저장까지 이어서 하려면 `training-nudge` Skill을 쓴다.

## 대상
| 인자 | 처리 대상 |
|---|---|
| 과정명(예: `정보보안`) | 해당 과정만 화면에 보고. 보고서는 전체 과정으로 갱신 |
| `all` 또는 빈 값 | 전체 과정 |

`data/교육과정.csv`에 없는 과정명이면 처리하지 말고 과정 목록을 알려 준다.

## 절차
1. **명단과 수료 기록 대조:** `CLAUDE.md`와 `data/*.csv`를 읽고 사번으로 대조한다. 직원·과정마다 기한(원본 명단 직원은 과정 기한 / `data/신규입사자예외.csv`의 사번은 `입사일 + 30일` / 그 외는 확인 필요)을 정하고, 이수 · 지연 · 기한 전 · 확인 필요와 기한 후 수료를 나눈다. 명단 외 사번과 과정명 불일치는 따로 모은다.
2. **부서별 이수율 표:** `report/교육이수.md` 1장을 쓴다. 과정마다 `**전체**` 행에서 이수 + 미이수 = 명단 인원인지 확인한다.
3. **미이수자 목록:** 2장(미이수자 목록)과 3장(확인 필요 항목)을 쓴다. 장 구성과 열은 `training-nudge` Skill 4-1을 따른다.
4. **검증:** `python scripts/verify.py`를 실행한다. 보고서 항목이 FAIL이면 고친 뒤 다시 실행한다.
   - 독려 초안 항목의 FAIL은 이 커맨드 범위 밖이다. 그대로 보고하고 `training-nudge`를 안내한다.

## 출력
```
| 과정 | 대상 | 이수 | 미이수 | 이수율 | 지연 | 기한 전 |   ← 과정별 전체 행
부서별 이수율이 가장 낮은 부서: 과정 · 부서 · 이수율
미이수 인원: 연인원 N명(실인원 M명) / 지연 인원: 연인원 N명(실인원 M명)
확인 필요: 명단 외 사번, 기한 후 수료, 신규 입사자 여부 확인 불가, 예외 근거 누락, 과정명 불일치 (없으면 "없음")
검증: 보고서 PASS | FAIL (FAIL 항목과 기대값)
```
