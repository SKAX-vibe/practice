# invoice-check

업무 규칙(역할, 계산서 합산, 판정 세 가지, 차액, 부가세, 표기, 제약)은 프로젝트 `CLAUDE.md`를 따른다. 여기에는 실행 순서와 단계별 완료 조건만 적는다.

**흐름:** 자료 읽기 → 기준 대조 → 불일치 식별 → 초안 작성 → 검증 → 검증 결과 저장 → 결과 보고

## 1. 자료 읽기
- `README.md`에서 기준일과 Pass 기준을 확인하고, `CLAUDE.md`를 읽는다.
- `data/발주.csv`와 `data/세금계산서*.csv`(전부)를 읽는다.
- 원본은 읽기만 한다.

## 2. 기준 대조
원본을 README의 Pass 기준과 `CLAUDE.md`에 비춰 확인한다.
- 발주 건수, 계산서 장수, 계산서 파일 수
- 계산서가 여러 장인 발주, 계산서가 없는 발주
- 발주에 없는 발주번호의 계산서, 발주와 거래처가 다른 계산서
- 공급가액의 110%처럼 부가세 포함이 의심되는 금액

결과를 사용자에게 한 줄로 알린다. 기준이 불명확하면(예: 같은 계산서번호 중복) 진행하기 전에 질문한다.

## 3. 불일치 식별
- 발주마다 판정(일치 / 금액 차이 / 계산서 없음)과 차액을 정한다. 판정별 건수 합 = 발주 건수인지 확인한다.
- 확인 요청 대상 = 일치가 아닌 발주. 거래처별로 묶는다.

## 4. 초안 작성

### 4-1. 대조표와 요약 → `report/대조.csv`, `report/대조요약.md`
- `CLAUDE.md`의 C트랙 공식 형식을 지킨다. 기존 파일 구조를 그대로 템플릿으로 쓴다. `verify.py`는 이 형식을 읽는다.
  - 요약 차액 문구는 `차액 합계(계산서−발주) **+N원**(절대값 M원)` 형식. 부호는 ASCII `+`/`-`, 0이면 `0원`
  - 2장 표 열: 판정 · 건수 · 공급가액 · 계산서 금액 · 차액. 행은 일치, 금액 차이, 계산서 없음, `**합계**`
  - 3장 표 열: 발주번호 · 거래처 · 공급가액 · 계산서 금액 · 차액 · 판정 · 비고 (일치가 아닌 건만)
  - 4장: 확인 필요 항목. 발주에 없는 계산서가 있으면 계산서번호를 적는다.
- 작성 직후 **5-1 집계 검증**을 실행한다. 대조표·요약 항목이 FAIL이면 4-2와 5-2를 건너뛰고 6단계로 간다.

### 4-2. 확인 요청 초안 → `outbox/drafts/확인요청_<거래처>.md`
- 불일치 발주가 있는 거래처마다 하나씩 쓴다. 기존 초안 하나를 템플릿으로 쓴다.
  - `## 2. 불일치 내역` 표 열: 발주번호 · 공급가액 · 계산서번호 · 계산서 금액 · 차액 · 판정
- 판정별 요청 내용
  - 금액 차이: 차이 사유와 수정·추가 발행 필요 여부 확인
  - 계산서 없음: 발행 여부, 계산서번호·발행일 또는 발행 예정일 확인
- 불일치가 해소된 거래처의 초안이 남아 있으면 지우지 말고 사용자에게 알린다.
- 수신자와 회신 기한은 `[확인 필요]`로 둔다. 발송하지 않는다.

## 5. 검증

### 5-1. 집계 검증
```
python scripts/verify.py
```
- 대조표, 요약, 확인 요청 초안 항목을 모두 확인한다. `결과: PASS`이면 5-2로 넘어간다.
- `결과: FAIL`이면 FAIL 항목과 기대값을 그대로 기록한다.
  - 원인이 결과물 작성 오류라면 4단계로 돌아가 고친 뒤 다시 검증한다.
  - 원인이 원본 형식이나 스크립트 쪽이라면 고치지 말고 사용자에게 알린다. 5-2는 미실행으로 둔다.
- `verify.py`는 수정하지 않는다.

### 5-2. 사실성 검토: 확인 요청 메시지
각 초안의 1장 메시지를 원본과 대조한다.
- 발주번호 · 계산서번호 · 금액 · 차액이 `report/대조.csv`와 같은지
- 차이 사유를 사실처럼 쓰지 않았는지. 예: "부가세를 포함해 잘못 발행하셨습니다"(X) → "부가세가 포함되어 있는지 확인 부탁드립니다"(O)
- 계산서 없음 건을 "발행하지 않았다"고 단정하지 않았는지. "기준일 현재 수취 내역에서 확인되지 않음"으로 쓴다.

문제 문장은 최소한으로 고친다. 사용자 판단 없이는 고칠 수 없는 문제가 남으면 FAIL이다.

## 6. 검증 결과 저장 → `report/검증결과.md`
실행할 때마다 덮어쓴다.

```markdown
# 검증 결과

- 실행일: YYYY-MM-DD (기준일: YYYY-MM-DD)
- 최종 결과: PASS | FAIL

| 검증 대상 | 방법 | 결과 | 실패 사유 |
|---|---|---|---|
| report/대조.csv + report/대조요약.md + outbox/drafts/확인요청_*.md | scripts/verify.py | PASS/FAIL | FAIL 항목과 기대값, 없으면 - |
| 확인 요청 메시지 | 사실성 검토 | PASS/FAIL/미실행 | 남은 문제, 없으면 - |

## 사실성 검토에서 고친 문장
- 수정 전 → 수정 후 (이유). 없으면 "없음"

## 확인 필요 사항
- 차이 사유, 수신자, 회신 기한 등
```

- **최종 결과는 두 검증이 모두 PASS일 때만 PASS다.**

## 7. 결과 보고
사용자에게 짧게 보고한다. 최종 결과는 `report/검증결과.md`와 같게 쓴다.
- 최종 결과(PASS/FAIL)와 실패 사유
- 판정별 건수, 차액 합계
- 확인 요청 초안을 쓴 거래처와 발주번호
- 생성하거나 수정한 파일, 확인 필요 사항
