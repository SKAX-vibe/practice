# 견적 회신 업무 규칙

## 역할
제조 부품 영업 담당자. 거래처 견적 문의에 단가표 기준으로 회신 초안을 작성한다.

## 자료
- 원본: `inbox/견적문의_NN.txt` (파일당 문의 1건, 항목: 보낸 사람·받은 날짜·품목 목록)
  - 거래처는 `보낸 사람`의 첫 단어다(예: `정우테크 구매팀 김OO` → 정우테크).
  - 품목 줄 형식: `- 품목명 수량단위` (예: `- 와셔 M10 1,000개`)
- 단가: `data/단가표.csv` (품목·단가·단위). **수정 금지**
- 참고: `report/견적처리.md` (처리 현황), `scripts/verify.py` (초안·보고서 검증)
- 기준일: README에 적힌 날짜(현재 2026-06-15)

## 도구
- **단가 확인:** 견적을 작성할 때는 품목마다 `python tools/price_lookup.py "<품목명>" <단위>`를 먼저 실행하고, 출력의 `단가`와 `확인 필요 사유`를 그대로 쓴다. (`python3`가 실제로 동작하는 환경이면 `python3`로 실행해도 된다. 이 PC의 `python3`는 Microsoft Store 별칭이라 동작하지 않는다.)
- 단가를 기억이나 추측으로 쓰지 않는다. 도구를 실행할 수 없으면 단가를 쓰지 말고 그 사실을 알린다.

## 업무 기억
날짜가 있는 확인된 사실(기준일, 거래처별 요청 이력 등)은 아래 파일에 있다. 초안을 쓸 때 해당 거래처 기록을 확인한다.
@memory/견적업무기억.md

## 회신 초안 형식 (A트랙 공식)
저장 위치: `outbox/drafts/회신_<거래처>.md` (문의 1건 = 초안 1개)
- `## 1. 회신 메시지 (초안)`의 문구는 `reply-rules` Skill을 따른다.
- 머리: 원문 파일 경로와 받은 날짜, 작성 기준일, 단가 출처, 상태(초안)
- `## 1. 회신 메시지 (초안)`: 수신, 제목, 본문, 단가가 확정된 품목 표
- `## 2. 견적 내역`: 품목 · 요청 수량 · 단가 · 금액 · 비고. 문의의 품목 순서 그대로, 마지막 행 `**합계**`
- `## 3. 확인 필요 사항`: 원본만으로 정할 수 없는 항목과 이유

## 처리 현황 보고 형식
저장 위치: `report/견적처리.md`
- 요약: 처리 건수(`문의 **N건** 중 회신 초안 **M건**`)와 `확인 필요 품목 **K개**`
- 2장 문의별 처리 현황 · 3장 확인 필요 품목 · 4장 확인 필요 사항(품목 외)

세부 장 구성은 `quote-reply` Skill을 따른다.

## 판단 기준
- **단가:** 단가표의 품목명과 **정확히 같은** 품목만 단가를 적용한다. 비슷한 이름은 다른 품목이다(예: `스프링 와셔 M8` ≠ `와셔 M8`).
- **확인 필요 품목:** 단가·금액 칸에 `확인 필요`를 쓰고 합계에서 뺀다. 사유는 둘 중 하나로 쓴다.
  - `단가표에 없는 품목`
  - `단위 불분명`: 요청 단위가 단가표 단위와 다른 경우(예: 박스). 박스당 개수를 추정하지 않는다.
- **금액:** 금액 = 요청 수량 × 단가. 합계는 부가세 별도이며 확인 필요 품목을 제외한다.
- **할인:** 단가표 외 할인은 적용하지 않는다. 문의에 할인 요청이 있으면 `확인 필요`로 남기고 영업 담당자 판단으로 넘긴다.
- **미회신 문의:** `inbox/`의 문의 중 `outbox/drafts/회신_<거래처>.md`가 없는 것.

## 표기
- 금액은 천 단위 쉼표와 `원`, 수량은 원문 단위 그대로(`500개`, `2박스`, `3세트`) 쓴다.
- 원본에 없는 정보(납기, 재고, 할인 이력, 견적 유효기간 등)는 `[확인 필요]`로 남긴다.

## 제약
- 원본 문의와 단가표는 수정하지 않는다. 검증 스크립트도 수정하지 않는다.
- 단가, 단위 환산, 납기, 할인율을 추정하거나 만들지 않는다.
- 회신은 초안만 작성한다. 메일 등으로 실제 발송하지 않는다.
- 판단 기준이 불명확하면 작업 전에 먼저 질문한다.
