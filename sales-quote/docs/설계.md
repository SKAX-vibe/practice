# 영업 자동화 에이전트 설계 (L06)

- 대상: `sales-quote` (트랙 A · 영업)
- 상태: **설계 문서. 에이전트는 아직 구현하지 않았다.**
- 범위: 신규 견적 요청 발견 → 요청 분석 → 단가표 대조 → 견적서 · 회신 초안 작성 → 발송하지 않고 보고

## 1. 목적 · 범위

- 신규 견적 요청 1건이 사람 개입 없이 "초안 · 미발송" 상태까지 가는 자동화 사이클을 정의한다.
- 사람이 개입하는 시점은 두 가지로 제한한다.
  1. **예외 확인**: 확인 필요 품목, 보류 문의, 원문 변경, 검증 실패
  2. **최종 발송**: 담당자가 초안을 검토한 뒤 직접 보낸다. 에이전트에는 발송 기능이 없다.
- 기존 도구를 다시 만들지 않고 재사용한다.
  - 판단 기준: `CLAUDE.md`
  - 단가 대조: `/quote` 절차 2단계
  - 초안 · 처리 현황 · 검증 형식: `quote-reply` Skill 4~6단계
  - 집계 검증: `scripts/verify.py` (수정 금지)

## 2. 현재 구조 요약

| 구성 | 역할 | 설계에 주는 제약 |
|---|---|---|
| `CLAUDE.md` | 단가 정확 일치, 확인 필요 사유 2종(`단가표에 없는 품목` · `단위 불분명`), 할인 미적용, 초안 형식, 발송 금지, "판단 기준이 불명확하면 먼저 질문" | 무인 실행 중에는 질문할 수 없으므로 확인 필요로 분류해야 한다 |
| `/quote [견적문의_NN \| all]` | 문의 1건 또는 전체를 단가표와 대조해 초안 작성. **이미 초안이 있으면 갱신** | 에이전트는 `/quote all`을 호출하지 않는다(기존 초안 덮어쓰기 위험) |
| `quote-reply` Skill | 미회신(= 초안 파일 없음) 문의의 초안 작성 → `report/견적처리.md` 갱신 → verify.py + 사실성 검토 → `report/검증결과.md`. 같은 거래처 문의가 2건이면 질문 | 무인 실행에서는 질문 대신 보류로 처리한다 |
| `scripts/verify.py` (수정 금지) | 초안 경로 `outbox/drafts/회신_<거래처>.md` 고정. inbox의 모든 문의에 초안과 보고서 행을 요구 | 보류 · 원문 변경 문의가 inbox에 있으면 FAIL을 피할 수 없다 |
| `inbox/견적문의_NN.txt` | `보낸 사람:` · `받은 날짜:` · `- 품목 수량단위` 줄 · 자유 문장(납기 · 할인 요청) | 거래처 = `보낸 사람`의 첫 단어 |
| `data/단가표.csv` (수정 금지) | 품목 · 단가 · 단위 | 정확히 같은 품목명과 단위만 금액을 계산한다 |
| `memory/` · `tools/` · `docs/` | 비어 있는 폴더 | 처리 대장 · 보조 스크립트 · 설계 문서 위치 |

## 3. 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| 신규 판별 | 처리 대장(`memory/처리대장.csv`) + 초안 파일 존재를 함께 본다 |
| 같은 거래처 복수 문의 | 두 번째 문의부터 보류, 확인 필요로 보고한다. 기존 초안은 건드리지 않는다 |
| 처리된 문의의 원문 변경 · 재실행 | 기존 초안을 덮어쓰지 않고 보고만 한다. 재작성은 담당자가 `/quote 견적문의_NN`으로 직접 요청한다 |
| 견적서 | 회신 초안의 `## 2. 견적 내역`을 견적서로 본다. 별도 견적서 파일은 만들지 않는다 |
| 해석 불가 품목 줄 | 초안 3장과 보고서 4장(품목 외 확인 사항)에 원문 줄 그대로 `[확인 필요]`로 적는다. 나머지 품목은 정상 처리한다 |
| 실행 방식 | 담당자 수동 실행 + `/loop` 주기 실행. 처리할 것이 없으면 파일을 바꾸지 않는다 |
| 실행 결과 기록 | `report/견적처리.md` · `report/검증결과.md` 갱신 + `report/실행로그.md` 누적 + 처리 대장 + 채팅 보고 |

## 4. 문의 분류 규칙

원문 지문 = 원문 텍스트(줄바꿈을 LF로 정규화)의 SHA-256 앞 12자리.

| 조건 | 분류 | 동작 |
|---|---|---|
| 대장 없음 · 초안 없음 · 같은 거래처의 다른 문의 없음 | **신규** | 자동 처리(2~5단계) |
| 대장 없음 · 같은 거래처의 다른 문의 있음 | **보류-거래처 중복** | 초안 없음, 예외 보고 |
| 대장 없음 · 지문이 다른 대장 항목과 같음 | **보류-중복 원문** (파일명만 다름) | 초안 없음, 예외 보고 |
| 대장 없음 · 초안 있음 | 기존 처리(대장 미등록) | 대장 등록만, 초안 변경 없음 |
| 대장 있음 · 지문 같음 · 초안 있음 | 처리 완료 | 건너뜀 |
| 대장 있음 · 지문 다름 | **원문 변경** | 초안 유지, 예외 보고 |
| 대장 있음 · 초안 없음 | 초안 없음(삭제 추정) | 재작성 안 함, 예외 보고 |
| `보낸 사람` 또는 `받은 날짜` 없음 | **보류-원문 형식** | 초안 없음, 예외 보고 |

"기존 처리(대장 미등록)"는 다음 세 경우를 흡수해 이력을 맞춘다.
- 첫 실행 시 이미 초안이 있는 01~03
- 초안 작성 후 기록 전에 중단된 사이클
- 담당자가 `/quote` · `quote-reply`로 직접 만든 초안

처리 대장 열(구현 시): 문의 파일, 거래처, 받은 날짜, 원문 지문, 초안 파일, 상태(처리 · 보류-거래처 중복 · 보류-중복 원문 · 보류-원문 형식), 기록일, 비고.

## 5. 6단계 실행 사이클

1. **신규 요청 발견**
   - inbox 전체를 4장 규칙으로 분류한다.
   - 신규 · 보류 · 원문 변경 · 대장 미등록이 모두 0이면 파일을 바꾸지 않고 "변경 없음"만 남기고 끝낸다.
2. **요청 분석**
   - 신규 문의마다 거래처, 받은 날짜, 품목 줄(품목 · 수량 · 단위), 품목 외 요구(납기 · 할인 등)를 뽑는다.
   - `- 품목 수량단위` 형식에 맞지 않는 줄은 해석 불가 줄로 따로 모은다.
3. **단가표 대조**
   - `/quote` 절차 2단계와 `CLAUDE.md` 판단 기준을 그대로 쓴다.
   - 품목명 정확 일치 + 단위 일치만 금액 = 수량 × 단가.
   - 나머지는 `확인 필요`(`단가표에 없는 품목` · `단위 불분명`). 할인 요청은 적용하지 않고 `확인 필요`.
   - 단가 · 단위 환산 · 납기 · 할인율을 추정하지 않는다.
4. **견적서 · 회신 초안 작성**
   - 신규 문의만 대상이다. 쓰기 직전에 `outbox/drafts/회신_<거래처>.md`가 없음을 다시 확인한다. 있으면 쓰지 않고 예외로 돌린다.
   - `quote-reply` 4-1 형식으로 작성한다. 상태는 "초안 · 미발송".
   - 해석 불가 줄은 3장 `[확인 필요]`에 원문 그대로 적는다.
5. **처리 현황 · 검증 · 이력 기록**
   - `quote-reply` 4-2: `report/견적처리.md`에 모든 문의를 반영한다. 보류 문의는 초안 칸에 `보류`, 해석 불가 줄은 4장에 적는다.
   - `quote-reply` 5 · 6: verify.py와 사실성 검토를 실행하고 `report/검증결과.md`에 기록한다.
   - verify.py FAIL은 원인을 구분해 기록한다: **보류로 인한 FAIL** / **원문 변경으로 인한 FAIL** / **작성 오류로 인한 FAIL**(이 경우만 4단계로 돌아가 고친다).
   - 원문 형식 오류로 verify.py가 실행되지 않으면 미실행으로 기록한다.
   - 처리 대장과 `report/실행로그.md`에 이번 사이클을 기록한다.
6. **발송하지 않고 담당자에게 보고**
   - 이 단계에서는 어떤 발송 · 연락 · 외부 호출도 하지 않는다. 보고만 한다.
   - 보고 항목:
     - 신규 처리 · 건너뜀 · 보류 · 원문 변경 · 대장 등록 건수
     - 확인 필요 품목(문의 · 품목 · 사유)과 품목 외 확인 사항
     - 검증 결과와 FAIL 원인 구분
     - 생성 · 수정 파일
     - 담당자 할 일: 예외 확인, 초안 검토, 직접 발송

## 6. 설계 검토 결과

| 확인 항목 | 결론 | 근거 · 단서 |
|---|---|---|
| 정상 문의는 사람 개입 없이 초안까지 가는가 | **가능 (조건부)** | 신규 · 다른 거래처 · 형식 정상인 문의는 1~5단계를 질문 없이 진행한다. 단, 도구 권한 승인 프롬프트가 뜨면 사람 개입이 생긴다(C3) |
| 같은 거래처 여러 문의와 원문 변경을 구분하는가 | **가능** | 다른 파일 + 같은 거래처 = 거래처 중복, 같은 파일 + 다른 지문 = 원문 변경, 다른 파일 + 같은 지문 = 중복 원문. 거래처명 표기가 다르면 구분하지 못한다(C6) |
| 기존 초안 보존과 중복 생성 방지가 되는가 | **지침 수준으로 가능** | 초안이 없음을 확인한 뒤에만 쓰고, 기존 파일은 쓰지 않는다. 기술적 차단 장치는 없다(C4) |
| `/quote` · `quote-reply` · `verify.py`와 충돌이 없는가 | **일부 충돌 있음** | `/quote`의 자동 갱신, `quote-reply`의 질문 단계, `verify.py`의 보류 FAIL. 아래 회피 규칙과 C1 · C2 · C5 참조 |
| 수동 · 주기 실행에서 이력이 일관되는가 | **가능 (조건부)** | 두 방식이 같은 대장 · 실행로그를 쓰고, 1단계의 "대장 미등록 흡수"로 외부 작성 초안과 중단된 사이클을 맞춘다. 동시 실행 방지는 지침 수준이다(C7) |
| 사람 개입이 예외 확인과 최종 발송으로 제한되는가 | **설계상 제한됨** | 무인 실행 중에는 질문하지 않고 예외로 분류해 보고한다. 권한 승인 프롬프트는 예외다(C3) |
| 6단계가 정확히 "발송하지 않고 보고"인가 | **충족** | 기록 작업은 5단계로 옮겼고, 6단계는 보고만 한다. 에이전트에 발송 기능이 없다 |

### 충돌 회피 규칙 (기존 파일을 수정하지 않고 에이전트가 지킬 것)
- `/quote all`을 호출하지 않는다. 단가 대조 규칙만 재사용한다.
- `quote-reply` 2단계의 "같은 거래처는 질문"은 보류로 대신한다.
- `CLAUDE.md`의 "판단 기준이 불명확하면 먼저 질문"은 무인 실행 중에는 확인 필요로 분류하는 것으로 대신한다. 기존 규칙과 다른 동작이므로 에이전트 지침에 명시한다.

## 7. 현재 구조의 제약 (에이전트를 구현해도 해결되지 않음)

| 번호 | 제약 | 원인 |
|---|---|---|
| C1 | 보류 · 원문 변경 문의가 inbox에 있는 동안 verify.py 결과는 FAIL이다 | 초안 경로 고정, 모든 문의에 초안 요구, verify.py 수정 금지 |
| C2 | 같은 거래처의 두 번째 문의는 초안을 만들 수 없다 | 초안 파일명 `회신_<거래처>.md` 고정 |
| C3 | 무인 실행이라도 도구 권한 승인이 필요하면 사람이 개입해야 한다 | 쓰기 권한 사전 허용은 설정 변경이 필요 |
| C4 | 기존 초안 덮어쓰기 금지는 지침과 쓰기 전 확인으로만 지켜진다 | 기술적 차단(hook) 없음 |
| C5 | 담당자가 `/quote` · `quote-reply`를 직접 실행하면 대장 갱신 없이 초안이 바뀔 수 있고, 다음 사이클은 이를 감지하지 못한다 | 대장은 원문 지문만 비교, 기존 도구는 대장을 모름 |
| C6 | 거래처명 표기 변형(예: "(주)정우테크")은 다른 거래처로 본다 | 거래처 = `보낸 사람` 첫 단어 |
| C7 | 주기 실행은 Claude Code 세션이 열려 있는 동안만 된다. 실시간 감지가 아니라 주기 확인이며, 동시 실행 잠금은 지침 수준이다 | `/loop`는 세션 안에서 동작. 클라우드 예약 실행(`/schedule`)은 로컬 inbox를 볼 수 없음 |
| C8 | 실제 발송 여부와 고객 회신은 추적하지 않는다 | 발송은 범위 밖 |

## 8. 향후 개선 (기존 파일 수정 또는 설정 변경이 필요)

| 개선 | 필요한 변경 | 해결 · 완화 |
|---|---|---|
| verify.py가 보류 목록을 인식하거나 문의 번호 기반 초안 파일명을 지원 | `scripts/verify.py` 수정 | C1 · C2 |
| `/quote` 3단계를 "단건 지정 시에만 갱신"으로, `quote-reply` 2단계가 대장을 보도록 수정 | `.claude/commands/quote.md`, `.claude/skills/quote-reply/SKILL.md` 수정 | C5 |
| 무인 실행 규칙(질문 대신 확인 필요) 명시 | `CLAUDE.md` 수정 | 규칙 충돌 |
| 출력 폴더 쓰기 권한 사전 허용, 기존 초안 덮어쓰기를 막는 PreToolUse hook | Claude Code 설정 변경 | C3 · C4 |
| 거래처 표준명 목록 | 새 참조 데이터 | C6 |

## 9. 구현 시 검증 계획 (참고)

임시 복사본에서 시험용 가상 문의로 확인한다. `new-data/L11`의 문의는 실습 규칙상 미리 사용하지 않는다.

1. 첫 실행: 01~03은 대장 등록만 되고 초안은 바이트 단위로 그대로다. verify.py PASS.
2. 신규 1건(다른 거래처): 초안 1개 생성, 보고서 · 대장 · 실행로그 갱신, verify.py PASS.
3. 재실행: 신규 0건, 파일 변경 없음(전후 해시 비교).
4. 같은 거래처 두 번째 문의: 보류로 보고, 기존 초안 무변경, verify FAIL 원인이 "보류"로 기록됨.
