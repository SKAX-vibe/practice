# quote-reply

업무 규칙(역할, 단가 적용, 확인 필요, 할인, 표기, 제약)은 프로젝트 `CLAUDE.md`를 따른다. 여기에는 실행 순서와 단계별 완료 조건만 적는다.

**흐름:** 자료 읽기 → 미회신 찾기 → 단가 대조 → 초안 작성 → 검증 → 검증 결과 저장 → 결과 보고

## 1. 자료 읽기
- `README.md`에서 기준일과 Pass 기준을 확인하고, `CLAUDE.md`를 읽는다.
- `data/단가표.csv`와 `inbox/*.txt`를 전부 읽는다.
- 원본과 단가표는 읽기만 한다.

## 2. 미회신 찾기
- 문의마다 거래처를 뽑고 `outbox/drafts/회신_<거래처>.md`가 있는지 확인한다.
- 초안이 없는 문의가 미회신이다. 목록을 사용자에게 한 줄로 알린다.
- 미회신이 없으면 초안은 쓰지 않고 5단계 검증으로 간다.
- 같은 거래처의 문의가 두 건 이상이면 파일 이름이 겹친다. 진행하기 전에 질문한다.

## 3. 단가 대조
미회신 문의의 품목마다 다음 중 하나로 정한다.
- 단가 적용: 품목명이 단가표와 정확히 같고 단위도 같음 → 금액 = 수량 × 단가
- `확인 필요` / `단가표에 없는 품목`
- `확인 필요` / `단위 불분명`
- 문의 본문의 할인 요청, 납기 문의 등 품목 외 요구도 따로 적어 둔다.

결과를 사용자에게 한 줄로 알린다(예: "04: 8품목 중 확인 필요 2개 — 너트 M10 3박스, 스프링 와셔 M8").

## 4. 초안 작성

### 4-1. 회신 초안 → `outbox/drafts/회신_<거래처>.md`
- 기존 초안 하나를 템플릿으로 쓴다. `verify.py`는 이 형식을 읽는다.
  - 머리의 `원문:` 줄에 `inbox/견적문의_NN.txt`를 쓴다.
  - `## 2. 견적 내역` 표 열: 품목 · 요청 수량 · 단가 · 금액 · 비고. 문의 품목 순서 그대로, 마지막 행 `**합계**`
  - 확인 필요 품목은 단가·금액 칸에 `확인 필요`, 비고에 사유를 쓴다.
  - 할인 요청이 있으면 3장에 `할인 ... [확인 필요]`를 한 줄로 쓴다.
- 1장 메시지에는 단가가 확정된 품목만 표로 넣는다. 확인 필요 품목은 "확인 후 안내"로만 쓴다.

### 4-2. 처리 현황 → `report/견적처리.md`
- 기존 보고서 구조를 유지하고 모든 문의(기존 + 신규)를 반영해 갱신한다.
  - 요약 문구: `문의 **N건** 중 회신 초안 **M건**`, `확인 필요 품목 **K개**`
  - 2장 표 열: 문의 · 거래처 · 받은 날짜 · 품목 수 · 견적 금액 · 확인 필요 · 초안. 마지막 행 `**합계**`
  - 3장 표 열: 문의 · 거래처 · 품목 · 요청 수량 · 사유. 사유는 `단가표에 없는 품목` 또는 `단위 불분명`만 쓴다.
  - 4장: 품목 외 확인 필요 사항(할인, 납기 등)

## 5. 검증

### 5-1. 집계 검증
```
python scripts/verify.py
```
- `결과: PASS`이면 5-2로 넘어간다.
- `결과: FAIL`이면 FAIL 항목과 기대값을 그대로 기록한다.
  - 원인이 초안·보고서 작성 오류라면 4단계로 돌아가 고친 뒤 다시 검증한다.
  - 원인이 원본 형식이나 스크립트 쪽이라면 고치지 말고 사용자에게 알린다. 5-2는 미실행으로 둔다.
- `verify.py`는 수정하지 않는다.

### 5-2. 사실성 검토: 회신 메시지
각 초안의 1장 메시지를 원문·단가표와 대조한다.
- 메시지의 품목·수량·단가·금액이 2장 표와 같은지
- 원문에 없는 약속을 사실처럼 쓰지 않았는지: 납기, 재고, 할인 적용, 견적 유효기간, 배송 조건
- 수신자 이름이 원문 `보낸 사람`과 같은지

문제 문장은 최소한으로 고친다. 사용자 판단 없이는 고칠 수 없는 문제가 남으면 FAIL이다.

## 6. 검증 결과 저장 → `report/검증결과.md`
실행할 때마다 덮어쓴다.

```markdown
# 검증 결과

- 실행일: YYYY-MM-DD (기준일: YYYY-MM-DD)
- 최종 결과: PASS | FAIL

| 검증 대상 | 방법 | 결과 | 실패 사유 |
|---|---|---|---|
| outbox/drafts/ 초안 + report/견적처리.md | scripts/verify.py | PASS/FAIL | FAIL 항목과 기대값, 없으면 - |
| 회신 메시지 | 사실성 검토 | PASS/FAIL/미실행 | 남은 문제, 없으면 - |

## 사실성 검토에서 고친 문장
- 수정 전 → 수정 후 (이유). 없으면 "없음"

## 확인 필요 사항
- 확인 필요 품목, 할인 요청, 납기 등
```

- **최종 결과는 두 검증이 모두 PASS일 때만 PASS다.**

## 7. 결과 보고
사용자에게 짧게 보고한다. 최종 결과는 `report/검증결과.md`와 같게 쓴다.
- 최종 결과(PASS/FAIL)와 실패 사유
- 처리 건수: 이번에 새로 쓴 초안 / 전체 문의
- 확인 필요 품목(문의 · 품목 · 사유)과 품목 외 확인 필요 사항
- 생성하거나 수정한 파일
